# Push notifications (Firebase Cloud Messaging)

The chat socket ([chat.md](chat.md)) only reaches people with the app open. When a message arrives for a participant with **no open socket**,
the server sends them a push through FCM (HTTP v1, `firebase-admin`). Code: `app/push/service.py`, `app/routers/devices.py`,
hook `notify_offline()` in `app/chat/hub.py`.

## Setup (once)

1. Create a project at [console.firebase.google.com](https://console.firebase.google.com) (free plan is enough).
2. Add an **Android app** with package name `mx.tec.sonrisas` and download `google-services.json` (it goes in the Android app, `sonrisas/app/`).
3. Project settings -> Service accounts -> **Generate new private key**. Save the JSON as `secrets/firebase.json` next to `docker-compose.yml`
   (`secrets/` is git-ignored and mounted read-only at `/run/secrets`).
4. In `.env`: `FIREBASE_CREDENTIALS_PATH=/run/secrets/firebase.json`, then restart the API.

Without `FIREBASE_CREDENTIALS_PATH` (or if the file can't be loaded) pushes are simply off and the API logs it at startup.

## Endpoints

| Route | What |
|---|---|
| `PUT /devices/{id}` `{"token": "<FCM token>", "platform": "ANDROID"}` | Register this installation, or refresh its token. `id` is generated by the app and kept. Any logged-in user. A token already registered by another user moves to the caller (shared phone, new login). Someone else's `id` is a 404. |
| `DELETE /devices/{id}` | Stop pushes to this installation. Call it on logout. |

Archiving or deleting a user removes all their devices (same place that revokes their refresh tokens).

## What is sent

A **data-only** message with `priority: high` and **ids only**, so no names or text pass through Google:

```json
{"type": "message", "child_id": "<uuid>", "message_id": "<uuid>"}
```

The app's `FirebaseMessagingService.onMessageReceived` then calls `GET /messages?child_id=...&since=...` (authenticated, same rules as always)
and builds the notification itself.

Who gets it: the child's PADRE, DOCENTE and ADMIN **that have no open socket**, minus the author, and only if their account is active (not archived or deleted).
Every registered device of such a user is notified. ORG and other families never are. Deleting a message sends no push.

Pushes are sent from a small thread pool and are best effort: a Firebase outage is logged and never affects sending or storing a message.
A token Firebase reports as `UNREGISTERED` / sender mismatch is deleted.

## What the Android app has to do

`firebase-messaging` + the `google-services` plugin; ask for `POST_NOTIFICATIONS` on Android 13+; `onNewToken` -> `PUT /devices/{id}`;
register once after login too; `DELETE /devices/{id}` on logout; create a notification channel.

Sources: [Send messages with the Firebase Admin SDK](https://firebase.google.com/docs/cloud-messaging/send/admin-sdk), [FCM message types](https://firebase.google.com/docs/cloud-messaging/concept-options).
